# LuoHai（海珞）

**表形式証拠 Skill**

LuoHai は、構造化された表形式の証拠抽出と引用のための、独立して利用できるオープンソース Skill です。標準ライブラリで OOXML ワークブックを読み取り、テーブル領域を検出し、ワークシートとテーブルのコンテキストを記録します。セルと範囲の証拠を出力し、生の値と表示値を区別して保持し、再検証できる引用を再構築します。曖昧性と損失は報告され、最初の一致で解決されることは決してありません。

* **LuoHai は単体利用に非公開の SeaFlow ベースを必要としません。** 単独で複製・テスト・利用できます。
* **SeaFlow との統合は任意です。** SeaFlow と併用する場合、LuoHai は公式の SeaFlow Skill／プラグインとして動作しますが、その統合は SeaFlow 側で実装されます。

## LuoHai が解決する問題

ワークブックは文書であり、データベースではありません。セルに見える値は、入力されたものかもしれず、共有文字列から継承されたものかもしれず、数式が生成したものかもしれず、あるいは単にセルが存在しないために欠けているのかもしれません。多くのツールはこれらのケースを黙って潰します。数式を評価し、数値を表示し、欠落を空文字列で埋めます。その結果は、ファイルに実際に書かれていた内容へもはやたどれません。

LuoHai は逆の立場を取ります。ワークブックを書かれているとおりに読み、生の値と表示値を分離し、セルが **empty**（存在するが空）なのか **absent**（シートに存在しない）なのかを明示し、エラーセルを空白ではなくエラーとして報告し、読み取らなかったものは捨てずに表面化させます。出力する各ユニットは、元のファイルに対して再検証できる引用を再構築できるだけの正確な座標を持ちます。

> **証拠を整理すること ≠ 証拠を創出すること**
> **Organising evidence ≠ creating evidence**
>
> LuoHai は、実際に観測した表形式の証拠を正規化し構造化します。欠落した値を捏造せず、ファイルが支えない事実を推論せず、汎用の分析エンジンとして振る舞いません。

## 機能

以下は Skill が実行時に宣言する機能です。記載のないものは実装されていません。

| 機能 | サポート | 内容 |
| --- | --- | --- |
| 表形式証拠ユニット | supported | 検出されたテーブル領域ごとに 1 つの証拠ユニットを出力し、それぞれがワークシートとテーブルのコンテキストを持つ |
| 引用の再構築 | supported | ユニットのペイロードがセル単位のアドレス、行ラベル、列見出しを保持し、ネイティブな引用を再構築できる |
| 範囲の特定 | supported | 矩形範囲はすべての座標を覆う引用として解決される — 矩形は穴を保ったまま |
| 空と不在 | supported | 存在するが空のセルは `empty`、シートに存在しないセルは `absent` — 異なる 2 つの事実 |
| エラー状態 | supported | エラーセルは空白ではなくエラーとして報告される |
| 数式テキスト | supported | 数式テキストは `<f>` から読み取られ、キャッシュ値とは分離して保持される |
| 非表示シートの状態 | supported | シートの状態は `workbook.xml` から読み取られる |
| 宣言されたテーブルの観測 | partial | OOXML のテーブルパート（`xl/tables`）を読み取り、推論された領域と突き合わせる。宣言されたメタデータが権威として扱われることはない |
| 結合セルの状態 | partial | 結合範囲を読み取る。覆われたアドレスは値ではなく merged-from として報告される |
| リッチテキストのラン | partial | インライン文字列と共有文字列は平坦化され、ラン単位の書式は失われる |
| 信頼度スコアリング | unsupported | 不確実性と損失の状態は記録するが、証拠のスコアリングやランキングは行わない |
| CSV 入力 | unsupported | 本スライスはアーキテクチャ上の決定により XLSX のみ |
| レガシー `.xls`（BIFF） | unsupported | バイナリ形式は解析しない。試すのではなく拒否する |
| 数式の評価 | unsupported | 読み取り専用。数式テキストは読み取るが、キャッシュ値の評価や再計算は行わない |
| 表示形式のレンダリング | unsupported | スタイルや表示形式のレンダリングは行わない。数値の表示値は生の値と等しい |
| セルのコメント | unsupported | コメントおよびスレッド コメントは読み取らない |
| 埋め込みオブジェクト | unsupported | グラフ、画像、OLE オブジェクト、ピボットテーブルは読み取らない |
| 大容量ファイルのストリーミング | unknown | ストリーミング経路は存在せず、パッケージ全体をメモリに読み込む |

LuoHai は実装している形式を読み取り、それ以外は推測せずに拒否します。

## 来歴はどのように保持されるか

* **生の値と表示値は分離したまま。** セルの表示値が、その由来である生の値を黙って置き換えることはありません。
* **空白セルは欠落セルではありません。** `empty` と `absent` は別の状態であり、別のものとして報告されます。
* **読み取らなかった内容は表面化させます。** コメント、図形、グラフ、メディア、ピボットテーブル、VBA は無視されず、未読コンテンツとして報告されます。したがって、きれいな読み取りがそれらを隠すことはできません。
* **宣言されたメタデータは権威ではありません。** パッケージ内で見つかったテーブル宣言は、実際に観測された領域と突き合わせられ、どちらも他方を上書きしません。
* **曖昧性は結果です。** セレクタが複数の位置に一致した場合はすべての候補を返し、いずれも選択しません。最初の一致によるフォールバックはありません。
* **証拠はバイト列に束縛されます。** ユニットは成果物の内容ダイジェストを保持するため、抽出された引用はそれが由来する正確なファイルに対して検証できます。

## インストール

決定論的な経路は標準ライブラリのみです。インストールするパッケージも、起動するサービスもありません:

```bash
git clone https://github.com/HuDeyi-66/Luo_Hai_Tables_Skill
cd Luo_Hai_Tables_Skill
python --version        # Windows + CPython 3.13.14 で適格性を確認済み
```

インストールはこれだけです。

## 最小の単体利用例

必須のサーフェスは 1 つの関数だけです:

```python
from skills.luohai import run_tabular_evidence

result = run_tabular_evidence("throughput.xlsx", source_id="ports")

print(result.is_complete_success)          # 何か失われていれば False
for unit in result.units:
    print(unit.address.value, unit.loss)   # 例: "A1:C3", ('empty', 'absent')
```

`run_tabular_evidence` は、ファイルシステムのパス、生のバイト列、または自分で構築した `TableArtifact` を受け取ります。返る実行結果には、証拠ユニット、実行診断、および読み取りが完全だったかについての正直な評価が含まれます。Skill が読み取れないワークブックでも、例外を送出するのではなく、損失または拒否を記録した結果を返します。

下位のエントリポイントもあります:

```python
from skills.luohai import TabularEvidenceSkill, TableArtifact, FixtureXlsxBackend

artifact = TableArtifact.from_file("throughput.xlsx", "ports")
result = TabularEvidenceSkill(FixtureXlsxBackend()).run(artifact, source_id="ports")
```

リポジトリには実行可能な例もあります:

```bash
python examples/luohai_table_example.py
```

## テスト

```bash
python tests/run_all.py --quiet
python fixtures/rebuild_and_diff.py --runs 3
python fixtures/rebuild_and_diff_table_context.py --runs 3
```

ランタイム、サービス、兄弟チェックアウト、外部パスは不要です。専用の分離スイートがそれを証明します。`skills/` 配下のいずれかのモジュールが非公開ランタイムの import を取得すると失敗し、パッケージの import がそのようなモジュールを読み込まないことを確認し、**本リポジトリのみ**をパスに含む新しいインタプリタからエントリポイント、例、および 2 つの決定性ハーネスを実行します。

### 任意の比較バックエンド

ロックされた `python-calamine` wheel は**本リポジトリでは配布されず**、ランタイム依存でもありません。記録された wheel を `.spike/python_calamine-0.8.2-cp313-cp313-win_amd64.whl` に置いた場合、その SHA-256 と拡張モジュールの SHA-256 が使用前に再確認されます。置かない場合、比較テストはスキップされます。クリーンなチェックアウトが報告するのはこの状態です。

```bash

```

## 既知の制約

* **OOXML ワークブックのみ。** `.xlsx` と `.xlsm` を読み取ります。レガシー `.xls` は試すのではなく、サポート対象外として宣言されます。CSV、PDF、OCR はありません。
* **数式の評価はありません。** 数式テキストは読み取りますが、キャッシュ値は評価ではなく、LuoHai が計算することもありません。
* **表示形式のレンダリングはありません。** 数値について、セルの表示値は生の値と等しくなります。
* **宣言されたテーブルに権威はありません。** 宣言されたテーブルメタデータは観測結果と突き合わせられ、どちらも権威として扱われません。
* **未読のパッケージパートは無視されず報告されます。** コメント、図形、グラフ、メディア、ピボットテーブル、VBA は未読コンテンツとして表面化します。
* **Skill をまたぐランキングはありません。** ここにあるものがテーブルを他と比較して順位付けすることはありません。
* **パッケージ全体をメモリに保持します。** ストリーミング経路がないため、非常に大きなワークブックは対象外です。
* **プラットフォーム適格性。** Windows + CPython 3.13.14 で確認済みです。決定論的な経路は標準ライブラリのみなので、この環境に固定されるものではありませんが、他のバージョンやプラットフォームは確認していません。

## SeaFlow との関係

LuoHai は、独立して公開される 2 つのオープンソース Skill の 1 つです。SeaFlow はこれを公式 Skill／プラグインとして統合できます。単体利用に非公開の SeaFlow ベースランタイムへのアクセスは必要ありません。

依存の向きは一方向です:

```
SeaFlow（非公開ランタイム）  ---適応--->  LuoHai（本リポジトリ）
```

LuoHai が SeaFlow を import することはありません。SeaFlow を一度も使わなくても、ここにあるものは変わりません。

* SeaFlow の公開情報入口: <https://github.com/HuDeyi-66/SeaFlow>

本節のリンクは**発見用リンク**であり、ランタイム依存の宣言ではありません。

## 海珊（ShanHai）との関係

海珊（ShanHai） — 法律テキスト証拠 Skill — は LuoHai の**兄弟 Skill** であり、依存ではありません。どちらの Skill も他方を import せず、その分離はテストで表明されています。

* ShanHai リポジトリ: <https://github.com/HuDeyi-66/Shan_Hai_Code_Skill>
